The role, in one breath

Why the plan has two halves

An FDE embeds with a customer and takes an AI platform the last mile: from "the model can do this in a demo" to "it runs inside their environment, on their data, past their security review, with their team trained to own it." Hiring tests both halves — most engineering candidates fail the second one.

half one · engineer

Build the thing

Agents, RAG, evals, full-stack prototypes, enterprise integration, private-cloud deployment, security posture. Tracks 0–4.

half two · consultant

Land the thing

Discovery, use-case selection, demo craft, workshops, solution briefs, engagement management. Track 5 — interleaved weekly, because it needs reps, not reading.

The six tracks

Sequenced; each closes with a capstone that is also a portfolio artifact

  • Track 0 — C++ close-out

    existing · 2 sessions

    Sessions 14–15 plus the open Phase 3/4 capstone debts. Not FDE-critical — pure closure so it stops occupying a dashboard slot. Do first, fast.

    Produces: finished course, archived; SPSC ring buffer + bench artefacts.

  • Track 1 — Claude Certified Architect, finish

    existing · ~6 sessions

    Directly on-path: SDK builds, PII handling, agent architecture. Session 12 (SDK Build A — prerequisites + PII) is queued and is exactly FDE material.

    Produces: certification + an agentic SDK app with PII-aware design. Portfolio piece #1.

  • Track 2 — FDE prototyping stack

    reshape ts course · ~8 sessions

    The dormant TypeScript course, reshaped with an FDE spine and trimmed after independent review — the role needs demo-shipping speed, not front-end craft. Ends with a deployed AI demo on public financial data (e.g. earnings-call Q&A).

    • Phase 1 (3): TypeScript fundamentals, typed API clients
    • Phase 2 (3): React essentials — a functional demo UI, streaming LLM output
    • Phase 3 (2): ship it — build + deploy the demo
    Produces: a live, public AI demo app. Portfolio piece #2 — the one you open in interviews.

  • Track 3 — Production AI systems

    new course · ~18 sessions

    The demo→production gap: what separates FDEs from demo-builders. Grown after independent review to carry the two most-tested axes — data plumbing and orchestration reliability.

    • Phase 1 (5): RAG deep-dive — chunking, embeddings, hybrid retrieval, reranking
    • Phase 2 (3): SQL & data integration — client-style messy sources (SQL, CSVs, APIs, docs)
    • Phase 3 (3): agent orchestration & tool-use reliability — LangGraph alongside Claude SDK/MCP, structured outputs
    • Phase 4 (4): eval harnesses — golden sets, LLM-as-judge, regression gates, prompt-eval iteration loops
    • Phase 5 (3): guardrails, prompt-injection defence, observability, cost/latency budgets
    Produces: RAG + agent system with a published eval report and a written trade-off memo. Portfolio piece #3 — rarest signal in the pile.

  • Track 4 — AWS & deployment for AI

    new course · ~8 sessions · aws per d1

    The biggest raw gap, trimmed to what enterprise buyers actually demand: deploy privately and wire SSO — not a certification-style survey of cloud services. Built on AWS end-to-end (D1).

    • Phase 1 (2): Docker, images, compose
    • Phase 2 (2): one AWS deploy path end-to-end — IAM and networking learned in service of it
    • Phase 3 (2): private deployment patterns — VPC, Bedrock private model access
    • Phase 4 (2): auth/SSO (OAuth, OIDC, SAML) + secrets management
    Produces: the end-to-end vertical flagship — client-style messy data → RAG + agent → evals → private deploy → recorded walkthrough. The Track 3–5 capstones converge here. Portfolio piece #4.

  • Track 5 — FDE consulting craft

    new · ~9 sessions · interleaved 1/week from week 1

    Starts in week one and threads through the entire path — reps over reading. It's the differentiator round in FDE loops, so it gets the most repetitions. Quizzes prove little here; every capstone is a performance artifact.

    • Discovery & scoping (2): stakeholder interviews, use-case selection, ROI framing
    • Ambiguous case-study drills (3): vague finance-vertical prompt → scoped plan in 45 min — the signature FDE interview round, rehearsed repeatedly
    • Demo craft (2): narrative structure, live-demo discipline, failure recovery
    • Written artifacts (1) + mock engagement (1): solution brief/SOW, then an end-to-end dry run
    Produces: recorded 10-min demo video + 1-page solution brief + discovery script. Portfolio pieces #5–6.

Design decisions — why this shape

The three calls that most changed the plan, with the trade-offs

Reshape the TS course as the prototyping track · chosen

  • TS/React is the de-facto FDE demo stack; Python alone reads as "notebook engineer"
  • Reuses an already-planned course instead of authoring a fourth new one
  • Con: delays deeper Python data tooling — acceptable, Python basics already exist from Building AI Apps

Separate cloud course, not folded into Production AI · chosen

  • Deployment is the biggest raw gap — folding it in would compress both topics below usefulness
  • Different capstone types: eval report vs architecture note
  • Con: one more course to author and schedule; total length grows ~4 sessions vs merged

Consulting craft interleaved weekly, not a block · chosen

  • Performance skills need spaced reps; a 2-week cram produces nothing durable
  • Keeps one demo/writing rep per week for the whole path — 20+ reps by the end
  • Con: harder to schedule; needs discipline to not skip when technical tracks are absorbing

One cloud deep, not two shallow — AWS per D1 · chosen

  • FDEs are expected to go deep on the customer's stack quickly — depth on one proves the ability
  • Second cloud is a fast transfer later; concepts (IAM, VPC, managed services) map 1:1
  • Con: a customer on the other cloud sees a first-time learner — mitigated by pattern-level fluency
